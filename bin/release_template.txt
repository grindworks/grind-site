Release title
v1.8.1 - Security Fixes

Release notes
This release fixes security issues found in an audit of v1.8.0, including a way to skip email two-factor authentication, a cross-site scripting issue in the Corporate theme, and client IP spoofing behind a proxy. We recommend updating all sites.

> [!IMPORTANT]
> **An update is performed by the version that is currently installed.** The changes listed under "Updater" take effect from your next update after this one.
>
> **Enabled bundled plugins are now updated.** Previously, an update never changed a bundled plugin you had enabled (for example `plugins/mail_otp_2fa.php`), so it did not receive fixes. After updating to v1.8.1, GrindSite Core replaces each enabled bundled plugin with the new version on the next page load, if you have not edited it. If you edited it (for example to set allowed IPs or passwords), it is not changed and the **Plugins** page shows "A newer bundled version is available" with instructions.
>
> **Theme files are updated only when themes are allowed to update:**
> - **From v1.7.4 or later:** Leave **"Do not update themes and skins"** unchecked (the default). Theme files that change are saved to `data/theme_backups/<date_time>/` first.
> - **From v1.7.3 or earlier:** The option is labeled **"Do not update/add themes and skins"** and is **checked** by default. While it is checked, the theme changes below are not applied. If you uncheck it, all bundled themes and skins are overwritten without saving copies, and deleted ones are restored, so copy any bundled theme you edited first.
>
> If you keep themes from updating, replace these files with the ones in `grindsite-v1.8.1.zip` (skip any theme you deleted, and re-apply your own edits):
> - **Security fix:** `theme/corporate/home.php`, `theme/corporate/archive.php`, `theme/classic/functions.php`, `theme/classic/home.php`, `theme/classic/search.php`
> - Other changes: `theme/corporate/parts/header.php`, `theme/classic/404.php`, `theme/default/parts/toc.php`, `theme/marketing/functions.php`, `theme/neo-minimalist/functions.php`, `theme/neo-minimalist/page.php`, `theme/neo-minimalist/single.php`

### 🔒 Security
- **Email two-factor authentication could be skipped:** With the Mail OTP (2FA) plugin enabled, a user who knew only the password could open the admin panel by adding `/logout.php` to a URL (for example `/admin/index.php/logout.php`). The Strict Session and Audit Logger plugins had the same check. They now recognize only the real `admin/logout.php`.
- **Corporate theme:** The hero title and text of a post were shown without escaping, so a user who can edit posts could run script in the browser of an administrator who views the page. They are now escaped. A post whose slug is the name of a theme template (`home`, `single`, `page`, `archive`, `category`, `tag`, `search`, `maintenance`) no longer selects that template.
- **Client IP behind a proxy:** With **Settings → System → "Trust Proxy Headers"** enabled, a client could set headers such as `Client-IP` or `CF-Connecting-IP` to change the IP address used by login lockout, the admin IP restriction and the rate limiter. GrindSite Core now reads only `X-Forwarded-For`, from the nearest proxy backwards, skipping the addresses in **"Trusted Proxy IPs"**. If you use Cloudflare or another CDN, enter its IP ranges there.
- **Session IDs:** When the session ID changes (every 15 minutes), the old ID now stops working after 60 seconds, so a stolen cookie cannot be used for the rest of the session.
- **Forged Host header:** Opening the admin login page with a forged `Host` header no longer changes the stored site address (used by the CLI) or clears the page cache; only a logged-in user who can manage settings records it. Page, sitemap, RSS and `llms.txt` caches are written only for the site's own address, so requests for other host names cannot fill the disk.
- **SMTP "SSL" was not encrypted:** With **Settings → Mail → Encryption: SSL**, the connection was made without encryption. It now uses implicit TLS, as on port 465. If mail stops working after the update, choose **TLS** for port 587 or **SSL** for port 465.
- **Basic Auth sample plugin:** The sample passwords (`password123`, `guest2024`) are no longer accepted, passwords are compared in constant time, and public URLs that contain `/admin/` (such as `/category/admin/`) are now protected. If you enabled this plugin without setting your own passwords, visitors will be asked for credentials you must now set in `plugins/basic_auth.php`.
- **Other hardening:** Post excerpts in the Classic and Corporate themes and translated attribute text in several themes are escaped. X (Twitter) and Instagram embeds match the exact host name. The unused-files cleaner can no longer move `.htaccess` or the trash folder. Admin layout values are validated, so an invalid value cannot break the admin panel. Line breaks in log messages can no longer forge log entries.

### 🛠️ Reliability
- **Strict Session plugin:** It no longer logs users out about every 15 minutes with "Your account was accessed from another device".
- **Code blocks:** Text that starts with `/` (for example `/usr/local/bin/php -v`) is no longer turned into a site URL when a post is saved. A code block saved before this release may still show your site address in front of such a path; open the post, correct the code and save it.
- **Meta description:** A post without a description no longer shows `{{CMS_URL}}` in its meta description.
- **Moving a database to a server without SQLite FTS5:** Saving posts no longer fails, and search falls back to simple matching.
- **Search:** URLs such as `?q[]=x` no longer cause a server error.
- **Rate Limiter plugin:** The API limit no longer applies to the admin panel, so bulk actions are not blocked.
- **Preview images** older than one hour are removed from `assets/uploads/_preview/`.
- **Link cards:** An empty response from the linked site shows an error message instead of a server error.

### ⬆️ Updater (applies to updates performed by v1.8.1 or later)
- **Failed update checks:** If GitHub cannot be reached, **Settings → Update** shows "Could not check for updates" instead of claiming the site is up to date.
- A download that exceeds the size limit is reported as failed instead of leaving a partial file.

## 🇯🇵 日本語 (Japanese)

v1.8.0 の監査で見つかったセキュリティ上の問題を修正しました。メールによる2要素認証を回避できる問題、Corporate テーマのクロスサイトスクリプティング、プロキシ配下でのクライアントIPのなりすましなどが含まれます。すべてのサイトで更新をおすすめします。

> [!IMPORTANT]
> **更新処理は、現在インストールされているバージョンが行います。** 下記「更新機能」の変更が有効になるのは、今回の次の更新からです。
>
> **有効化した同梱プラグインも更新されるようになりました。** これまでは、有効にした同梱プラグイン（例: `plugins/mail_otp_2fa.php`）はアップデートで変更されず、修正が届きませんでした。v1.8.1 に更新すると、次にページを開いたときに、編集していない同梱プラグインは新しいバージョンに置き換わります。編集している場合（許可するIPやパスワードの設定など）は変更せず、**プラグイン** 画面に「同梱の新しいバージョンがあります」と手順を表示します。
>
> **テーマのファイルは、テーマの更新を許可している場合にのみ更新されます。**
> - **v1.7.4 以降から:** **「テーマとスキンを更新しない」** をチェックなし（初期状態）のままにしてください。変更されるテーマのファイルは、事前に `data/theme_backups/<日付_時刻>/` に保存されます。
> - **v1.7.3 以前から:** オプション名は **「テーマとスキンを更新・追加しない」** で、初期状態で**チェックが入っています**。チェックが入ったままだと、下記のテーマの変更は適用されません。チェックを外すと、同梱テーマとスキンはすべて上書きされ（コピーは保存されません）、削除したものも復活します。同梱テーマを独自に変更している場合は、事前にコピーしておいてください。
>
> テーマを更新しない場合は、次のファイルを `grindsite-v1.8.1.zip` 内の同じファイルで置き換えてください（削除済みのテーマは対応不要です。独自の変更は反映し直してください）。
> - **セキュリティ修正:** `theme/corporate/home.php`、`theme/corporate/archive.php`、`theme/classic/functions.php`、`theme/classic/home.php`、`theme/classic/search.php`
> - その他の変更: `theme/corporate/parts/header.php`、`theme/classic/404.php`、`theme/default/parts/toc.php`、`theme/marketing/functions.php`、`theme/neo-minimalist/functions.php`、`theme/neo-minimalist/page.php`、`theme/neo-minimalist/single.php`

### 🔒 セキュリティ
- **メールによる2要素認証を回避できた問題:** Mail OTP (2FA) プラグインが有効な場合、パスワードだけを知っている人が、URL に `/logout.php` を付けるだけ（例: `/admin/index.php/logout.php`）で管理画面を開けました。Strict Session と Audit Logger のプラグインも同じ判定をしていました。今後は本来の `admin/logout.php` だけを判定します。
- **Corporate テーマ:** 記事のヒーローのタイトルと本文をエスケープせずに表示していたため、記事を編集できるユーザーが、そのページを開いた管理者のブラウザでスクリプトを実行させることができました。エスケープするようにしました。また、テーマのテンプレート名と同じスラッグ（`home`、`single`、`page`、`archive`、`category`、`tag`、`search`、`maintenance`）の記事が、そのテンプレートで表示されることはなくなりました。
- **プロキシ配下のクライアントIP:** **「システム設定 → システム → プロキシヘッダーを信頼する」** が有効な場合、`Client-IP` や `CF-Connecting-IP` などのヘッダーを付けることで、ログインのロックアウト、管理画面のIP制限、アクセス回数制限に使われるIPアドレスを変えられました。今後は `X-Forwarded-For` だけを、サーバーに近いプロキシから順に読み、**「信頼するプロキシIP」** のアドレスを飛ばして判定します。Cloudflare などの CDN をお使いの場合は、その IP アドレス帯を入力してください。
- **セッションID:** セッションIDが変わったとき（15分ごと）、古いIDは60秒後に使えなくなるようにしました。盗まれた Cookie がセッションの間ずっと使える状態ではなくなりました。
- **偽装された Host ヘッダー:** 偽装した `Host` ヘッダーで管理画面のログインページを開いても、保存されているサイトのアドレス（CLI が使用）が変わったり、ページキャッシュが削除されたりしなくなりました。記録するのは、ログイン中で設定を管理できるユーザーのアクセスだけです。ページ、サイトマップ、RSS、`llms.txt` のキャッシュはサイト本来のアドレスに対してのみ作成し、ほかのホスト名へのリクエストでディスクが埋まらないようにしました。
- **SMTP の「SSL」が暗号化されていなかった問題:** **「システム設定 → メール設定 → 暗号化方式: SSL」** では、暗号化せずに接続していました。今後は 465 番ポートと同じ暗黙の TLS で接続します。更新後にメールが送れなくなった場合は、587 番ポートなら **TLS**、465 番ポートなら **SSL** を選んでください。
- **Basic 認証のサンプルプラグイン:** サンプルのパスワード（`password123`、`guest2024`）では認証できなくなり、パスワードを定数時間で比較し、`/admin/` を含む公開URL（`/category/admin/` など）も保護するようにしました。独自のパスワードを設定せずにこのプラグインを有効にしていた場合、閲覧者は認証を求められるため、`plugins/basic_auth.php` でパスワードを設定してください。
- **その他の強化:** Classic と Corporate テーマの記事の抜粋、いくつかのテーマの属性内の翻訳テキストをエスケープするようにしました。X（Twitter）と Instagram の埋め込みは、ホスト名が完全に一致する場合だけ扱います。未使用ファイルの整理で `.htaccess` やゴミ箱フォルダを移動できないようにしました。管理画面のレイアウトの値を検証し、不正な値で管理画面が表示できなくなることを防ぎました。ログのメッセージ中の改行で、ログを偽造できないようにしました。

### 🛠️ 信頼性
- **Strict Session プラグイン:** 約15分ごとに「別の端末からアクセスされました」とログアウトされることがなくなりました。
- **コードブロック:** `/` で始まる文字列（例: `/usr/local/bin/php -v`）が、記事の保存時にサイトのURLに変換されなくなりました。このリリースより前に保存したコードブロックでは、そのようなパスの前にサイトのアドレスが表示されていることがあります。記事を開いてコードを直し、保存してください。
- **メタディスクリプション:** 説明文のない記事のメタディスクリプションに `{{CMS_URL}}` が表示されなくなりました。
- **SQLite の FTS5 が無いサーバーへのデータベースの移動:** 記事の保存が失敗しなくなり、検索は通常の一致検索で動作します。
- **検索:** `?q[]=x` のような URL でサーバーエラーにならなくなりました。
- **Rate Limiter プラグイン:** API の回数制限が管理画面に適用されなくなり、一括操作が止まらなくなりました。
- **プレビュー画像:** `assets/uploads/_preview/` の1時間以上前のプレビュー画像を削除するようにしました。
- **リンクカード:** リンク先から空の応答が返った場合に、サーバーエラーではなくエラーメッセージを表示するようにしました。

### ⬆️ 更新機能（v1.8.1 以降が行う更新に適用）
- **更新の確認に失敗した場合:** GitHub に接続できない場合、**「システム設定 → アップデート」** で「最新です」ではなく「更新を確認できませんでした」と表示するようにしました。
- サイズの上限を超えたダウンロードは、途中までのファイルを残さず、失敗として扱うようにしました。
